Project Summary

FinTrack is organized as a full-stack personal finance tracker. The frontend handles the user experience, the backend exposes secure endpoints, and Supabase PostgreSQL stores the main data.

Auth

Secure Access

Users register and log in as system operators. Passwords are hashed, and successful login returns a JWT session token.

Transactions

Financial Records

Users add income or expense records with amount, date, category, status, and description.

Budgets

Budget Tracking

The app compares spending against monthly and category limits, then calculates remaining budget and projected spending.

Alerts

Notifications

Budget and category warnings are generated when spending becomes high or exceeds configured limits.

Frontend Functionality

The frontend is an Angular application located in fin-track/. It provides the full user interface and communicates with the backend through ApiService.

Auth Page

Allows account creation and login. It handles loading states and displays validation or server errors such as invalid credentials.

  • Route: /auth
  • Uses register and login endpoints
  • Stores the JWT token after login

Overview Dashboard

Summarizes the selected month with income, expenses, net balance, remaining budget, savings rate, budget progress, spending by category, and recent transactions.

  • Route: /overview
  • Month selector controls reporting period
  • CSV report download is available

History Page

Displays all matching transactions and supports search, date-range filtering, category filtering, status filtering, type filtering, refresh, and CSV export.

  • Route: /history
  • Header search redirects here with a query
  • Mobile record cards use compact two-column content

Budgets Page

Calculates total monthly budget, total spent, remaining amount, daily average, projected spending, and per-category budget status.

  • Route: /budget
  • Users can add and update category limits
  • Users can create and fund savings goals

Add Transaction Page

Provides a form for recording a new transaction. After successful saving, the app refreshes budget notifications and returns to the overview.

  • Route: /add-transaction
  • Validates required fields
  • Rejects non-positive amounts

Settings Page

Lets the user update account email, upload or remove an avatar, and change the account password.

  • Route: /settings
  • Avatar preview updates the header
  • Password form validates confirmation

Notifications Page

Shows budget and category alerts generated from transaction and budget data. Notifications can be marked as read or cleared.

  • Route: /notifications
  • Unread count appears on the bell icon
  • Alerts are persisted locally

Header and Sidebar

The shared layout provides search, avatar, notification access, logout, navigation, and a responsive mobile sidebar menu.

  • Desktop sidebar remains visible
  • Mobile uses a menu button and overlay
  • Logout is available in header and sidebar context

Support Page

Provides project support information and contact details in a responsive layout.

  • Route: /support
  • Designed as an informational page
  • Accessible from the sidebar footer

Backend Functionality

The backend is an Express server located in fin-track-backend/. It manages authentication, database access, API routes, and server-side validation.

Express Server

The server starts from server.js and listens on PORT or 3000 by default.

npm run dev
http://localhost:3000

CORS Protection

The server accepts local Angular development origins such as localhost:4200, 127.0.0.1:4200, and similar ports in the 4200 range.

Authentication Middleware

Protected routes use authenticateToken. It reads the bearer token from the request header and rejects missing or expired sessions.

Database Initialization

On startup, ensureDatabase() creates required tables if they are missing. This makes first setup easier after connecting Supabase.

API Endpoints

The API base URL used by the frontend is http://localhost:3000/api. Protected routes require an Authorization: Bearer token header.

Method Endpoint Authentication Purpose Main Response
GET / No Checks whether the API is running. API name, database type, and status.
POST /api/auth/register No Creates a system operator account. Created user data or duplicate account error.
POST /api/auth/login No Authenticates a user by username and password. JWT token and user profile data.
GET /api/auth/me Yes Loads the current logged-in user. User id, username, email, and avatar.
PATCH /api/auth/profile Yes Updates email and avatar. Updated profile data.
PATCH /api/auth/password Yes Changes the logged-in user's password. Password update confirmation.
GET /api/transactions Yes Lists all transactions for the current user. Array of normalized transactions.
POST /api/transactions Yes Creates a new income or expense record. Created transaction data.

Database Design

The backend uses Supabase PostgreSQL through the pg package. The connection is configured in fin-track-backend/db.js.

Core Application Flows

These flows describe how the main features work across the frontend, API, backend, and database.

Authentication Flow

  1. User enters username and password on the auth page.
  2. Angular sends credentials to the login endpoint.
  3. Express finds the user and compares the bcrypt hash.
  4. Backend returns a JWT token and user profile.
  5. Frontend stores token and user data in local storage.

Transaction Flow

  1. User submits a transaction form.
  2. Angular validates required fields and amount.
  3. API receives a protected request with the JWT token.
  4. Express validates type and amount.
  5. PostgreSQL stores the transaction for that user.

Budget Flow

  1. Budget page loads transactions from the API.
  2. Frontend filters records by selected month.
  3. Expense totals are grouped by category.
  4. Local category limits are applied.
  5. UI displays status, progress, and remaining budget.

Notification Flow

  1. Transactions and budget limits are inspected.
  2. Budget usage and category usage are calculated.
  3. Alerts are generated for high or exceeded spending.
  4. Unread count updates the notification bell.
  5. Notifications can be read or cleared.

Client Storage and Persistence

FinTrack uses Supabase for persistent server data and local storage for frontend-only state that is not yet saved in the backend.

Storage Area Key or Table Purpose
Supabase PostgreSQL system_operators User accounts, hashed passwords, emails, and avatar Data URLs.
Supabase PostgreSQL transactions Income and expense records owned by each logged-in user.
Local storage fintrack_token JWT token used by the frontend for authenticated API requests.
Local storage fintrack_user Cached user profile used by the header and settings page.
Local storage fintrack_budget_limits Editable category budget limits.
Local storage fintrack_savings_goals Savings goals, target amounts, saved amounts, and monthly plans.
Local storage fintrack_notifications Generated budget alerts and read/unread status.

How to Run the Project

Run the backend and frontend in two separate terminals. The backend must be connected to Supabase before the frontend can register, log in, or save records.

Backend

Install dependencies, configure the environment file, and start the Express API.

cd fin-track-backend
copy .env.example .env
npm install
npm run dev

Frontend

Install dependencies and start the Angular development server.

cd fin-track
npm install
npm start
Important local URLs

Backend: http://localhost:3000. Frontend: http://localhost:4200. API base in the Angular service: http://localhost:3000/api.

Implementation Notes

These notes explain the most important design choices in the current version of the application.

Security

Passwords are never stored as plain text. The backend hashes them with bcrypt, then uses JWT tokens for authenticated API access.

Responsiveness

The application uses a desktop sidebar and a mobile slide-in menu. Mobile pages reduce text sizes and card spacing to fit narrow screens.

Reports

The overview, history, and budget pages can export CSV files so users can keep offline financial records.
